# H2 — MCP remoto do GitHub aceita credencial injetada pelo servidor

**Veredito: confirmada, com ressalva** sobre o tipo de credencial (`@modelcontextprotocol/sdk` 1.32.1, 2026-10-20).

## Objetivo
Verificar se `https://api.githubcopilot.com/mcp/` aceita `Authorization: Bearer` montado pelo servidor, e levantar
as tools de leitura e os argumentos que identificam o repositório.
Código: `spikes/h2/client.ts`. O token vem de `gh auth token` em tempo de execução; não é impresso nem gravado.

## Comandos e saída
```
$ cd spikes/h2 && npm ci && npx tsx client.ts
initialize ok: github-mcp-server
tools/list: 46 tools
get_file_contents isError: false bytes: 2619     # README.md de um repo do usuário
```
Os três passos responderam na primeira execução. Reexecuções posteriores falharam por rede
(`ConnectTimeoutError` e `Request timed out` para o mesmo host; `curl` oscilava entre 401 e timeout). Sem retry no
spike. A falha ocorre na conexão, não na autenticação.

## Tools de leitura (`readOnlyHint=true`) e argumentos de repositório
| Tool | Identifica o repositório por |
|---|---|
| `get_file_contents` | `owner`, `repo` (+ `path`, `ref`, `sha`) |
| `get_commit`, `list_commits`, `list_branches`, `list_tags`, `list_releases`, `get_latest_release`, `get_release_by_tag`, `get_tag`, `get_label` | `owner`, `repo` |
| `list_issues`, `list_pull_requests`, `issue_read`, `pull_request_read` | `owner`, `repo` (+ número e `method`) |
| `list_repository_collaborators`, `run_secret_scanning` | `owner`, `repo` |
| `list_issue_fields`, `list_issue_types` | `owner` obrigatório, `repo` opcional |
| `search_code`, `search_commits`, `search_repositories` | só `query` (qualificador `repo:` no texto) |
| `search_issues`, `search_pull_requests` | `query`; `owner` e `repo` opcionais |
| `get_me`, `get_teams`, `get_team_members`, `search_users`, `ui_get` | sem repositório |

## Insumo para a #14
A allowlist por repositório valida `owner` e `repo` nas tools estruturadas. Nas tools `search_*` o repositório
fica dentro de `query`: o gateway deve exigir e conferir o qualificador `repo:` ou bloquear essas tools.

## Limitações
- A credencial foi o token OAuth do `gh`. Um PAT de serviço dedicado não foi testado.
- Só leitura foi exercitada.

## Se falhar
O gateway expõe as tools do GitHub por API REST (ADR-0001, Confirmação, hipótese 2).
